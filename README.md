# 🏔️ Гравитационное влияние рельефа: бэкенд и API

[Документация и проверка API](https://gravity-api-service.fastapicloud.dev/docs) · [Репозиторий проекта](https://github.com/tester170/Gravity_API_Service)

---

## 🎯 Назначение проекта

При обработке гравиметрических данных необходимо учитывать влияние топографических масс на гравитационное поле. В проекте реализован подход, объединяющий приближённый физический расчёт и модель машинного обучения: исходная оценка гравитационного влияния рельефа дополняется коррекцией, рассчитанной по его морфометрическим характеристикам.

Для определения коррекции используется **Ridge-регрессия** — линейная регрессионная модель с регуляризацией. При обучении модель устанавливает зависимость между девятью характеристиками рельефа и расхождением исходного расчёта с опорным полем SRTM2gravity. При обработке новых данных она прогнозирует это расхождение, которое затем прибавляется к исходной оценке. Все значения выражены в **мГал**.

Приложение продолжает практическую работу модуля 4 по учёту влияния рельефа при обработке гравиметрических данных. В этом проекте ранее обученная модель включена в состав серверного приложения и доступна для использования через API.

## 🏗️ Как организована работа приложения

**Бэкенд** — часть приложения, которая подготавливает данные, выполняет расчёт и формирует результат. Здесь он реализован на Python, а обработка запросов организована с помощью **FastAPI**.

**API — программный интерфейс**, через который другие программы обращаются к функциям бэкенда. Он определяет доступные операции, состав передаваемых данных и формат ответа. В этом проекте программа отправляет характеристики рельефа по HTTP-запросу и получает расчётные значения либо HTML-страницу с картой.

Программа, отправляющая запрос, называется **клиентом**. Это может быть скрипт Python, мобильное приложение или веб-приложение. **Серверное приложение** принимает запрос, применяет модель и возвращает результат клиенту.

Такое разделение позволяет использовать одну модель в разных приложениях, не устанавливая её и библиотеки машинного обучения на каждое устройство. Бэкенд можно запустить на собственном компьютере или разместить на удалённом сервере. Если структура API сохраняется, для подключения клиента к другому серверу достаточно изменить адрес.

## 📥 Входные данные

Сервис принимает **заранее рассчитанные характеристики рельефа**. Загрузки произвольной цифровой модели рельефа или передачи только координат недостаточно.

Демонстрационный файл `terrain_demo.csv` содержит 6400 центров ячеек на участке Северного Кавказа. Данные выбраны из растрового фрагмента размером 1°×1° с идентификатором `N43E042`: каждая 15-я строка и колонка, без отбора по ошибке модели.

| Столбец | Содержание |
|---|---|
| `latitude`, `longitude` | Широта и долгота в EPSG:4326, градусы. Используются для карты и не входят в признаки модели |
| `elevation_m` | Высота, м |
| `slope` | Модуль градиента высоты, м/м; не угол наклона в градусах |
| `curvature` | Сумма вторых производных высоты по формуле из пособия, 1/м |
| `tpi_7`, `tpi_31`, `tpi_121` | Разность высоты ячейки и средней высоты в окне 7×7, 31×31 или 121×121 ячеек, м |
| `roughness_7`, `roughness_31` | Стандартное отклонение высот в соответствующем окне, м |
| `relief_31` | Разность максимальной и минимальной высот в окне 31×31, м |

Признаки подготовлены по **Copernicus DEM GLO-90**, приведённой к сетке 1/1200°. При подготовке собственных данных необходимо сохранить определения признаков, сетку, размеры окон и единицы измерения. Рассчитать эти характеристики заново по прореженной демонстрационной таблице нельзя.

Параметры стандартизации сохранены вместе с моделью в `StandardScaler`. Дополнительная нормализация входных данных не требуется.

## 📊 Результаты расчёта

Метод `POST /predict` принимает список записей в формате JSON. При `output=json` сервер возвращает координаты и три расчётных значения:

| Поле | Содержание |
|---|---|
| `baseline_mgal` | Исходная аппроксимация: притяжение промежуточного плоскопараллельного слоя при плотности 2670 кг/м³ с дополнительными членами по TPI |
| `correction_mgal` | Прогноз модели для разности «опорное поле − исходная аппроксимация» |
| `prediction_mgal` | Сумма исходной аппроксимации и прогнозируемой коррекции |

При `output=html` сервер возвращает HTML-страницу с интерактивной картой. Для исходного и уточнённого расчётов используется общая цветовая шкала; для коррекции — отдельная шкала, симметричная относительно нуля. Подсказка каждой точки содержит все три значения.

Библиотека Plotly встроена в HTML-файл. Для загрузки картографической подложки требуется подключение к интернету.

Программа `check_api.py` отдельно запрашивает числовые результаты и карту, поэтому расчёт выполняется дважды. Полученные файлы сохраняются на компьютере пользователя, а не на сервере.

## 🚀 Локальный запуск

Установите **Python 3.12**, скачайте проект с GitHub через **Code → Download ZIP** и распакуйте архив. Откройте папку проекта в VS Code.

В терминале Windows создайте виртуальное окружение и установите зависимости:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Если PyPI недоступен, можно использовать зеркало:

```powershell
.venv\Scripts\python.exe -m pip install -r requirements.txt --index-url https://repo.huaweicloud.com/repository/pypi/simple
```

Для проверки вычислений без запуска API выполните:

```powershell
.venv\Scripts\python.exe gravity_backend.py
```

Запустите сервер и оставьте терминал открытым:

```powershell
.venv\Scripts\python.exe -m uvicorn api:app --host 127.0.0.1 --port 8001
```

Откройте [http://127.0.0.1:8001/docs](http://127.0.0.1:8001/docs). В разделе `POST /predict` нажмите **Try it out**, вставьте содержимое `data/request_example.json` в тело запроса и нажмите **Execute**.

Страница документации позволяет проверить оба формата ответа, но HTML показывает как код. Чтобы обработать демонстрационную таблицу и открыть саму карту, выполните во втором терминале:

```powershell
.venv\Scripts\python.exe check_api.py
```

Программа создаст:

- `results/terrain_predictions.csv` — таблицу результатов;
- `results/terrain_map.html` — интерактивную карту.

При повторном запуске эти файлы перезаписываются. Для остановки сервера нажмите **Ctrl+C** в первом терминале.

На Linux и macOS окружение создаётся командой `python3.12 -m venv .venv`; вместо `.venv\Scripts\python.exe` используется `.venv/bin/python`. При запуске на `127.0.0.1` сервер доступен только с этого компьютера.

## ☁️ Подключение к облачному серверу

Проверить опубликованный сервис можно через [интерактивную документацию](https://gravity-api-service.fastapicloud.dev/docs). Для работы с этой страницей достаточно браузера.

Чтобы выполнить расчёт через облачный сервер из программы `check_api.py`, укажите в ней:

```python
API_URL = "https://gravity-api-service.fastapicloud.dev/predict"
```

После этого запустите клиент обычной командой. Локальный сервер запускать не требуется: вычисления выполняются удалённо, а CSV и HTML сохраняются на вашем компьютере.

В настройках мобильного приложения указывается базовый адрес **без `/predict`** — путь запроса добавляется программой автоматически.

Отдельная главная страница не предусмотрена, поэтому обращение к `/` может возвращать 404. Для проверки используйте `/docs`. Доступность сервиса зависит от работы платформы размещения.

## 🌐 Развёртывание собственного сервера

1. Создайте репозиторий GitHub, включив создание **README.md**. Нажмите точку в английской раскладке, чтобы открыть редактор `github.dev`.
2. Добавьте Python-модули, `requirements.txt`, `pyproject.toml`, папки `models`, `data` и `assets`. Файлы `api.py` и `pyproject.toml` должны находиться в корне репозитория. Виртуальное окружение, кеши, результаты расчётов и конфиденциальные данные загружать не нужно.
3. В разделе **Source Control** добавьте файлы в коммит, укажите сообщение и выполните **Commit & Push**.
4. Войдите на [FastAPI Cloud](https://fastapicloud.com/) через GitHub, предоставьте доступ к нужному репозиторию и выберите его при создании приложения.
5. Оставьте поле **Root Directory** пустым. Для данного проекта переменные окружения не требуются. Нажмите **Create App** и дождитесь завершения развёртывания.
6. Откройте адрес созданного приложения, добавив `/docs`.

Файл `pyproject.toml` определяет требования к Python, зависимости и точку входа `api:app` — объект `app` из модуля `api.py`. Секция `tool.setuptools` перечисляет модули проекта. При изменении зависимостей необходимо согласовать их версии в `requirements.txt` и `pyproject.toml`.

GitHub используется для хранения исходного кода, FastAPI Cloud — для выполнения серверного приложения. Если развёртывание завершилось ошибкой, проверьте журнал сборки, наличие модели и конфигурационные файлы.

Подробнее: [документация FastAPI Cloud](https://fastapicloud.com/docs/getting-started/existing-project/).

## 🧠 Обучение и оценка качества

Модель подготовлена по материалам [учебного пособия «Учёт влияния рельефа местности при обработке гравиметрических данных с применением методов машинного обучения»](https://colab.research.google.com/drive/1GhhSI4HkN_Vo5xQDmu-kFpgASuKWBlr-?usp=sharing).

Коэффициент регуляризации выбран по данным Алтая, после чего модель обучена на семи регионах. Северный Кавказ использован для независимой проверки и исключён как из обучения, так и из подбора параметров. Параметры стандартизации рассчитаны только по обучающей выборке.

На 100 000 контрольных ячеек Северного Кавказа получены следующие значения среднеквадратической ошибки относительно опорного поля:

| Вариант расчёта | RMSE, мГал |
|---|---:|
| Исходная аппроксимация | 19,30 |
| После коррекции Ridge | 15,82 |

Эти показатели относятся к контрольной выборке пособия, а не к демонстрационной таблице из 6400 точек. Снижение общей ошибки не означает улучшения в каждой точке. Применение модели к другим территориям требует отдельной оценки качества.

В качестве опорных данных используется **расчётное поле SRTM2gravity**, а не результаты полевых гравиметрических измерений. Файл `terrain_reference.csv` содержит опорные значения и контрольные расчёты для сравнения; в запрос к модели он не включается.

Для загрузки используйте только доверенные файлы `.joblib`: этот формат допускает выполнение кода при чтении.
